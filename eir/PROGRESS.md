## 2026-11-05 第 3 步：实现（Claude Code）

**状态**：完成。代码 `eir.py`（工作副本 `work\artifact\`，从 `cpcm_sa\work\artifact\` 复制，`src\` 与 `third_party\` 逐文件一致，`.gitignore` 已排除）。一个进程只跑一个任务脚本，E3 的注入在子进程内存中完成。

任务类型：`pre`（故障前 T̂、链路忙碌与 CB 排名、迁移量的参照）；`l1`（R0 + L1，W、L2-Global、L2-Local 都从这个文件出发，保证是同一个 L1 输出）；`rep`（W、L2G、L2L）；`full_e3`；`full`（A3h）。

交接说明没有写死、这里定下的做法（**待用户过目**）：

1. **T̂ 与最终评估的广播**：缓存先用 E3 恢复的广播路由填好（所以 R0 与 E3 相同），之后 T̂ 和最终后端评估都用同一张含缓存广播的图。第 2 阶段的最终评估是重新跑一次完整广播，这里不同，因为 L1 可能改了广播路由，部署的就是这张图。
2. **L1 的备选路径**：避开目标链路的最短路径，最多枚举 256 条，按路径上的当前忙碌之和取最闲的 3 条；广播只生成一棵替代树。DDR 端口不转发。一轮尝试一条，n = 10 次连续没改进就结束；另设总尝试上限 300 防止失控（冒烟中最多 121 次，没触发）。
3. **距离**：曼哈顿距离按全局核网格（`e3._grid_xy`）算，DDR 端口按它挂接的角落核算。交接说明的“同 Die 或曼哈顿距离 R 跳以内”按此理解，没有另外把同 Die 全部算进去，否则 R = 0 也会覆盖整个 Die。
4. **L2-Local 的连带问题**：搬动计算行为时，artifact 按 `generated_split_location`（从不更新）重建它读权重的通信，读源可能变回集合外的 DDR。这算违反“连带移动受限”，所以这种提议一律撤销，步数照算，记 `n_illegal`。
5. **温度**：判定“恶化”沿用第 2 阶段的规则（CPCM 方法要求 T̂ 变大，只改变距离项不算）。
6. **W 的能量归一化**：按 L1 输出重新取基准。
