## 2. 系统八组合：准确计数方式

暂沿 WP3 的 WSC-LLM/FACE 两种硬件，D 组采用同一个由既定规则选择的 PF4；三相位 0.1/0.5/0.9，后端种子 1/2/3。M 表示 A1→A3h，R 表示 R0→EIR，S 表示启用最终冻结的 DSTU。

| MRS | 映射及修复 | DSTU |
|---|---|---|
| 000 | A1-R0 | 无 |
| 100 | A3h-R0 | 无 |
| 010 | A1-EIR | 无 |
| 001 | A1-R0 | 有 |
| 110 | A3h-EIR | 无 |
| 101 | A3h-R0 | 有 |
| 011 | A1-EIR | 有 |
| 111 | A3h-EIR | 有 |

完整比较为 `2×1×3×3×8=144` 个联合逻辑单元。每臂为18项。

| 定版情况 | 既有可复用臂 | 联合新增上限 |
|---|---|---:|
| DSTU 保持旧 All256+C4 | 000、110、101、111 | 72 |
| DSTU 改为本轮新策略 | 000、110 | 108，再扣本轮已生成且身份完全相同的111结果 |

旧联合结果的映射、物理故障、释放时刻、公共期限、配对单跑与后端种子逐项匹配后才扣除。100、010、001、011 等新增臂的单跑另外生成，并按实际完整图身份去重；不能从144直接推导需要144次P单跑和144次D单跑。

A1-EIR 的新增准备需要单独记账。现有 F/G `fg_fault.py` 对 A1 的 l1 作业只计算 R0，并没有运行 A1 的 L1/L2。两硬件×4个 decode 算子为8个新增 L1；若全部进入 L2，则5种子对应40个“故障算子×种子”组合，每组合可能运行30/100/300档，最多120个L2作业。实际按原停止规则减少，不把40误写成40次FULL或固定40个作业。已有健康与R0状态继续复用。

健康场景的 R 是恒等，不重复八个相同组合。Split 只在 PE 故障使用，PF4 八组合不因此增加臂。

## 3. H/I 的模板现状与先行核对

四套模板均已存在：

- `third_party/isca2026-busybarn-artifact/models/intra_mapping_llama_prefill/`
- `third_party/isca2026-busybarn-artifact/models/intra_mapping_llama_decode/`
- `third_party/isca2026-busybarn-artifact/models/intra_mapping_qwen3moe_prefill/`
- `third_party/isca2026-busybarn-artifact/models/intra_mapping_qwen3moe_decode/`

每套都有 LN、MHA、projection、FFN 以及 BusyBarn/Gemini 模板字符串。主硬件用 BusyBarn 2×2，每Die 4×4核；第二硬件使用冻结的 WATOS 参数。长度/KV建议沿用2048；模型内按自己的模板比较，跨模型报告工作量差异。

| 模板事实 | Llama | Qwen3-MoE |
|---|---:|---:|
| 原生 batch | 8 | 16 |
| hidden | 8192 | 2048 |
| 总头数 | 64 | 32 |
| 每头维度 | 128 | 64 |
| 当前 MHA 微图头数 | P/D均8 | P/D均7 |
| 建议修正后的微图头数 | 8 | P/D均8 |
| 对应层 MHA 乘数 | 8 | 4 |
| FFN 中间维度 | 28672 | 模板同时列普通FFN 6144、专家FFN 768 |
| 专家数/top-k | — | 128/8 |

Qwen 的两阶段 `heads=7` 都需要在新生成入口修正，不仅 prefill；不能复制 GPT 的×8聚合。Llama 与 Qwen MHA 的 `cache_list` 都只加入 Kᵀ/V，保持这一工作负载，不能机械应用以 GPT 名称判断的过滤器。

两模型 decode FFN 都自带一次 RMSNorm，prefill FFN 不带这一次。按图核对后，单层应采用 `P=2×RMSNorm+h×MHA+projection+FFN`、`D=RMSNorm+h×MHA+projection+FFN`，h分别为8/4。原 artifact 的 `fig_endtoend/end_to_end.py` 对所有模型统一×8与2×LN，需要在新汇总入口按实际图修正。

Qwen3-MoE 模板使用固定的 `expert_idx % 16` 将128个专家分给batch中的16份输入，并显式构造Dispatch、专家计算、归约和Combine。当前图体现这套固定专家负载；它没有数据驱动的动态路由分布实验。先逐项统计专家输入字节、有效计算、归约与Combine，不将该模板结果写成已覆盖动态专家失衡。Llama/Qwen模板中的具体注意力结构也按实际图记录，不从目录名推断额外的GQA配置。

原生batch 8/16 是目前已确认的模板事实。建议H/I默认保留，若下一阶段决定统一batch再显式更新任务与复用统计；本轮没有改写模板。

## 5. H/I 的故障与联合部分

交接已确定主硬件完整P/D和代表故障、第二硬件各一个共同规则选出的PF4；具体代表故障集合在下一阶段计划中固定。建议采用以下紧凑覆盖：

- 主硬件每模型PF4作用于全部8算子，共16个算子故障单元；另每模型选择一个PE受损的projection/FFN点，共2个单元。若Split成立，至少其中一例验证Split，继续保留R0/刚性EIR/Local-m1对照。
- WATOS每模型PF4作用于已测的P/D MHA、FFN，共8个单元；不拼接未测LN/projection成完整模型结果。
- 以上建议合计26个A3h故障算子单元；最多130个种子组合、390个L2档位作业，另计R0/L1。实际早停会减少运行量。这里是下一阶段候选安排，尚未创建运行清单。
- 不新增MF6 FULL作为前置要求。GPT已有多硬件和96/144核结果继续保留，新模型不再铺全部规模。
- H/I联合使用定版DSTU和模型自己的完整D链、真实KV字节及公共窗口。联合臂、健康/PF4覆盖和配对单跑数量在模型图可构造后一次列清，避免把未测算子或GPT的KV头数直接搬入新模型。

## 6. 耗时如何更新

新模型的完整估时需要8类主硬件算子和4类WATOS算子的代表运行。现有WP2先回答执行提速，不能把约3倍的广播前图推演速度当成868次搜索的完整速度。

旧Qwen decode FFN报告的1000步中位：A1搜索592.8秒、末尾评估1563.1秒；A3h搜索2008.4秒、评估1372.0秒。它们来自历史机器与并行条件，只能说明评估成本需要单列，不能作为当前128核服务器的完成时间承诺。

下一批先检查两模型P/D的LN、MHA、projection、FFN图与Gemini适配；短构造用于核对头数、RMSNorm和专家输入。随后每模型、每硬件选prefill MHA/FFN与decode MHA/FFN的代表候选，先按A3h的g0/seed123测16项完整作业；旧Qwen decode FFN可复用质量状态，但计时需要在当前服务器独占测一个代表。记录初始化、校准、每步SA、十种子后端、随机选优、状态导出和峰值RSS，再补A1/Gemini代表核对各方法成本。新搜索的小批计入正式候选，计时重评与复用状态分别标记。

总进程小时按各类“剩余数量×实测完整作业时间”相加；墙钟按依赖、128进程上限与内存安排计算，并保留最长单任务限制。每进程NumPy/BLAS/Numba保持单线程，轻任务与大图混排，系统余量按用户指定3GiB。实际完成后继续三分钟COS、完整本地归档与清单核对。

## 7. J：算法定版后的计时

等价提速只更新效率结果。DSTU与EIR-Split如果改变方法，使用各自的新质量结果；旧All256+C4和刚性EIR的结果保持可查。
