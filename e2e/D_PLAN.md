## 1. 问题

同一晶圆（同一个 2×2 组）上 prefill 与 decode 同时服务，故障已发生并修复后，比较：

- **基线（BusyBarn）：** A1 映射 + artifact 原后端仲裁（长度分层，不切块） + R0 或 FULL-BusyBarn；
- **CRISP：** A3h 映射 + EIR 主力修复（L2Gsync，ε = 2%）+ DSTU（全链路 256 KB 切块 + 按跳后端 + C4）；

以及逐个去掉一个模块的消融。指标是重叠下的 TPOT、TTFT、请求延迟、L̂，以及 C 已有的迁移量与修复步数。

## 2. 场景：哪些流重叠，P 与 D 放在哪里

### 2.1 现有代码能表达什么（事实）

- **平台相同：** GPT prefill 与 decode 的 2×2 配置文件 `config_ch2x2_bw256_co4x4_bw256_t128x64_failpattern0.cfg` 逐字节相同（`diff` 核对，C 的工作副本）。所以两个阶段的映射可以放进同一个平台对象。
- **多流合并：** E4a 的 `e4_overlap.rename_stream` / `merged_events` 把各流事件 tag 的第 2 位改成 10 + 流号，合并成一张图；`e4_backend.stream_of` 按这一位识别流；释放时间实现 (b)：无依赖事件的开始时间 = 所属流的释放时刻。按跳后端 `event_driver_e4b`（提速版 `e2e\fast_hop.event_driver_fast`，逐位相同）、原后端规则的多流版 `e4_backend.event_driver_e4` 都接受 `release`。DSTU 的 a1、a2 场景就是这样把几个算子流放在同一个 2×2 上。
- **切块：** `dstu2.chunk_by(ev, hp, UNI["256all"])`（全链路 256 KB，o = 0）。W1 下 prefill MHA 切块后约 6.6–6.7 万个事件，W0 约 7.4–7.6 万（`out\b1.json`，10 个映射）；decode MHA W1 约 730 个。
- **重叠流已在各算子的图里，不用新造：**
  - prefill 写 KV：W1 的 prefill MHA 最终广播保留 K、Kᵀ、V、P，共 256 条消息发往 32 个 DDR 端口（`b1.json`：`bc_events` 256）。
  - decode 读 KV：decode MHA 的 QKᵀ、PV 从 DDR 读 K、V 形状的离线权重（共享历史 KV 口径，B4）。
  - 两者共用 DDR 端口及角落核与 DDR 之间的链路；各算子自己的激活与权重流共用片内链路与 D2D。设备与链路一次只服务一个事件，所以重叠时会互相排队。
  - 写的是新一批请求的 KV，读的是正在 decode 那一批的历史 KV，两者之间没有数据依赖，作为相互独立的流合并是对的。
- **C 的修复结果可直接复用：** EIR 的 sink 存有可重新加载的完整映射，`keep_final` 写 `final_snap`，l1 作业写 `R0_snap`、`L1_snap`，`child_reload` 在同一故障平台上加载后复算 T 并比较（`eir\eir.py` 第 1470–1490、1531–1538 行）。FULL 的快照在 `full\snaps\`，Colab 结果 3,360 个（`colab_results\c\full\full\snaps`），修复 sink 1,750 个（`colab_results\c\rep\rep`），另有本机分片的。
- **C 的数字都是原后端：** C 的修复、FULL 与后端评估都走 EIR 的原后端（BusyBarn 规则，不切块，地址哈希）。没有任何按跳后端或切块的运行。

### 2.3 推荐场景：S-A 同组时分（P 与 D 在同一个 2×2 组）

- **P 流：** 一个 prefill 算子（LN、MHA、投影、FFN 四种之一）的图，释放时刻 0。
- **D 流：** 一个 decode 步的串行链（第 2.2 节），释放时刻 τ = f × T_P（T_P 是该 P 流在同一臂、同一故障下的单独延迟），f ∈ {0.1, 0.4, 0.7}。
- **为什么选这三个 f：** 让 D 链整条落在 P 的运行区间内。C 中故障后最长的 decode 步约 0.5M 周期（A1 R0 的 TPOT 最大 +39.7%，约 49.7 万），最短的 P 是 prefill LN（约 2.1M），f ≤ 0.76 时都能落进去。
- **一个“重叠单元”** = 臂 × 故障 × P 的算子 × f × 后端种子。种子 1–3，同 DSTU。

**量级（事实，B4 W1 A3h 故障前）：** prefill 的一层 1.04 亿周期，其中 LN 2 × 2.14M、MHA 8 × 6.12M、投影 6.55M、FFN 44.0M；decode 的一层 24.3 万周期。一个 prefill 层的时间里大约跑 430 个 decode 步，所以不能把整层 P 与整串 D 放进一张图（推测要几百万个事件），只能按“单元”采样，再组装。

### 2.4 组装（近似，汇总里标明）

- **TPOT（重叠）：** TPOT′ = Σₚ wₚ × TPOT(p)。TPOT(p) 是 D 链在 P 算子 p 上的延迟（C_D − τ），对 f 与种子取均值；wₚ 是 p 在 prefill 一层中的时间占比（2·LN、8·MHA、投影、FFN，用同一臂同一故障的单独延迟）。
- **TTFT（重叠）：** 每个 decode 步给 P 带来的延迟 ΔPₚ = C_P（重叠）− C_P（单独），同种子配对。假设 decode 持续进行（每个 P 算子运行期间 decode 步一个接一个），T′ₚ = Tₚ / (1 − ΔPₚ / TPOT(p))，TTFT′ = 2T′_LN + 8T′_MHA + T′_proj + T′_FFN。这是线性叠加，不是整层仿真。
- **请求延迟：** 两种都报，并列不混写。
  - R-iso：B4 / C 的组装，不考虑重叠。
  - R-ov：TTFT′ + 输出长度 × TPOT′，输出长度 128、512、2048，等于“每个 decode 步都与 prefill 重叠”的情形（持续混合负载）。
- 每个单元的原始数（TPOT(p)、ΔPₚ、L̂）也单独列出，以便换别的占空比重新组装。
- **噪声：** ΔPₚ 与 P 的种子波动同量级，所以配对报告，同时列出 P 单独运行 3 个种子的极差；ΔPₚ 小于极差的格子标出。推测：prefill FFN（4,400 万周期，1% 约 44 万）上这种格子会很多。
- LN 计数：链里的 dc_ffn 图自带 1 个 LN，所以重叠行只有“原样”口径；不重叠行两种都报（同 B4）。

## 3. 对比的臂

| 臂 | 映射 | 故障后 | 后端与仲裁 | 状态从哪来 |
|---|---|---|---|---|
| B-R0（基线） | A1 | R0 | 原后端，不切块 | C 的 A1 l1 `R0_snap` |
| B-FULL（基线） | A1 | FULL-BusyBarn 胜者 | 原后端，不切块 | C 的 FULL-BB 快照（按后端选的胜者） |
| **CRISP** | A3h | L2Gsync 停止档 | 按跳后端，全链路 256 KB，C4 | C 的修复 sink（第 3.1 节取法） |
| −DSTU | A3h | L2Gsync 停止档 | 原后端，不切块 | 同 CRISP |
| −DSTU 优先级 | A3h | L2Gsync 停止档 | 按跳后端，全链路 256 KB，P1（切块但无优先级） | 同 CRISP |
| −EIR | A3h | R0 | 按跳后端，全链路 256 KB，C4 | C 的 A3h l1 `R0_snap` |
| −CPCM 映射 | A1 | L2Gsync 停止档（**要新跑**，第 3.2 节） | 按跳后端，全链路 256 KB，C4 | 新的修复 sink |
| （可选）FULL-A3h + DSTU | A3h | FULL-A3h 胜者 | 同 CRISP | C 的 FULL-A3h 快照 |
| （可选）φ_res | A3h | L2Gsync 停止档 | 按跳后端，事件级 φ_res 选切 + C4 | 同 CRISP |

- **无故障：** CRISP 与 −EIR 相同，B-R0 与 B-FULL 相同，只跑一次。
- **两条流时 C4 的顺序（事实，按定义推出）：** d̂ = r + k·T̂。D 链的 d̂_D = τ + k·T̂_D，P 的 d̂_P = k·T̂_P。在 τ < k(T̂_P − T̂_D) 时（本方案的 f 下总成立）C4 都让 D 先走。所以这里的 C4 就是“decode 优先”，T̂ 的精度不改变顺序。T̂_P 仍按 DSTU 口径算一次（按跳模式、切块后的图），这样 C4 与 DSTU 的实现一致。
- **反序参照（可选）：** P 先、D 后的固定顺序。有了它，CRISP 行可以报 BestFixed（两种顺序中好的那个），口径同 DSTU；代价见第 7 节。
- **φ_res 只作可选增强：** 默认不跑。

### 3.1 CRISP 用 C 的哪个修复状态（规则，开跑前写进 PROGRESS）

- 每个“故障 × 算子”的停止档按 C 的 ε = 2% 规则已经定了（`C_SUMMARY.md` 第 2.7、3.7 节）。
  - 停在 R0 或 L1：用 A3h l1 作业的 `R0_snap` 或 `L1_snap`，没有种子之分。
  - 停在 s30、s100、s300：该档有 5 个 SA 种子，取 C 后端均值为 5 个中位数的那个种子（并列取种子号小者）。
- 推荐只取 1 个种子：5 个全跑，CRISP 臂的按跳运行要乘 5。
- 迁移量、修复步数直接引用 C 的数（同一个快照）。

### 3.2 −CPCM 映射：A1 起点上的 L2Gsync（C 没有跑）

- C 在 A1 起点上只有 R0、L1（l1 作业）和 FULL-BusyBarn，没有跑 L2Gsync。
- 做法（推荐）：规则同 C（5 个种子，ε = 2%）。按 ε 规则分轮跑：先用 C 已有的 L1 判断，没进 ε 的算子跑 s30，仍没进的跑 s100，再 s300。停止档的种子取法同第 3.1 节。
- 替代（不跑新搜索）：用 A1 + FULL-BusyBarn + DSTU 代替。缺点是修复方法也换了，不是只去掉 CPCM 映射。

## 5. 指标

| 指标 | 内容 |
|---|---|
| TPOT | 每个单元的 TPOT(p)（C_D − τ），组装后的 TPOT′，相对同一臂的单独 TPOT、相对 B-R0 |
| TTFT | 每个单元的 ΔPₚ（配对）与 P 的种子极差；组装后的 TTFT′ |
| 请求延迟 | R-iso 与 R-ov 两种，输出 128、512、2048 |
| L̂ 与截止时间 | 口径同 DSTU：dᵢ = rᵢ + k·Tᵢ，k = 1.5，Tᵢ 是同一臂、同一故障、同一后端配置下的单独延迟（3 个种子均值），L̂ᵢ = (Cᵢ − dᵢ)/Tᵢ，报 L̂_D、L̂_P、L̂_max 与违约流数。C4 用的 d̂ᵢ 用 T̂ᵢ（CPCM 按跳模式） |
| 迁移量与修复步数 | 引用 C（第 2.6、2.7、3.6、3.7 节）；−CPCM 臂用新跑的 |
| 其他 | T̂ᵢ 对 Tᵢ 的误差；按跳审计（同 DSTU 自检 3）；各单元原后端与按跳后端的单独延迟对照（换后端本身带来的变化单列，不算进 DSTU 的收益） |

**比较口径。** 全部运行用 tag 哈希（同 W1 补跑方案乙），所以 D 自己的单独延迟与 C 的数（地址哈希）不会逐位相同。D 的表一律用 D 自己测的单独延迟作参照；与 C 的数只按均值对照。

## 6. 观测模式：decode 完成即停止

- **做法：** 在按跳后端的提速版副本里，D 链的最后一个事件结束的那个 tick 处理完就退出。
- **为什么能省：** D 链只有 24–49 万周期，P 是 210 万–4,400 万周期，停止时 P 只跑了它的一小部分。但图的构建、切块和 C4 的 T̂ 不省，所以实际省多少要实测（第 8 节 D0）。
- **验证（开跑前，不通过就不用这个模式）：** 同一配置、同一种子，各跑一次完整与停止模式。停止时刻前结束的每个事件的开始与结束时间、链路与设备记录、审计、D 链完成时刻，全部逐位相同。
  - 对象：pf_ffn A3h C4 f = 0.4、pf_ln A1 P1 f = 0.1、pf_mha A3h C4 f = 0.7，各 1 个种子，无故障；再加 1 个故障（PF4）。
- **用在哪里：** 只要 TPOT、L̂_D 的单元（f × 种子的全部 9 个）用停止模式；ΔPₚ 要 P 跑完，用完整运行。完整运行也给出 TPOT(p)，与停止模式同种子的那一格作为持续核对。
- **原后端不用这个模式：** 原后端不切块，单次只有几秒到两分钟（第 7 节）。

- −DSTU 优先级臂与 CRISP 共用 P 单独与 T̂ 的条件：单独运行在只有一条流时 C4 与 P1 的发放是否相同，冒烟时逐位核对。相同就共用，这个臂只要重叠运行，约 6.8 h。不相同就照全量算。

## 8. D0：开跑前的探针与自检（放行后第一步）

1. 加载 C 的快照：8 个算子 × {A1 R0、A1 FULL-BB 胜者、A3h R0、A3h 修复停止档、FULL-A3h 胜者}，各取 1 个故障（PF4）与无故障起点。T 与 C 存的相同（`child_reload` 的判据）；W1 删去条数核对。
2. prefill 4 个算子：`tag_facts`、改名、合并后的 owner 检查；全链路 256 KB 的块数与事件数（补上 pf_ln、pf_proj）。
3. 按跳完整一次与 C4 T̂ 一次：pf_ln、pf_proj 的 A1、A3h，各 1 个种子。记墙钟与单进程内存峰值，重估第 7 节。
4. decode 链：单独运行与 12 个算子之和对照；链的依赖检查。
5. 单流时 C4 与 P1 的按跳发放是否逐位相同（决定 −DSTU 优先级臂能否共用单独运行）。
6. 停止模式与完整运行的逐位比较（第 6 节的 4 个对象）。
7. 审计、释放时间、字节与路由树守恒（同 DSTU 自检 3–5）。

任何一项不通过就停下报告。比较规则（第 3.1 节的取法、第 2.4 节的组装、第 5 节的口径）在 D1 开跑前写进 `PROGRESS.md`，之后不改。

## 9. 需要用户定的问题（每个附推荐与理由）

1. **场景：** S-A 同组时分（P、D 在同一个 2×2 组），还是 S-B 分组（2×4 上 P 组、D 组分开，KV 经组间 D2D 传到 D 组的 DDR）。
   - **推荐 S-A 作 D 的主体。**
     - 现有的多流合并、释放时间、按跳后端、切块都能直接用，C 的快照可以直接复用。
     - 同一个故障同时作用于 P 和 D，与 C 的语义一致。
   - S-B 要新造平台改写和 KV 传输事件，而且故障坐标要重新定义（坏哪个组）。若要做，作为 D 之后的单独一步，先只读核实可行性。
2. **TTFT 怎么得到：** 单个 decode 步的 ΔPₚ 加线性叠加（第 2.4 节），还是重叠下只报 TPOT、L̂，TTFT 只报不重叠的。
   - **推荐前者，同时报每个单元的原始数和噪声地板。**
     - 不报 TTFT′ 就看不出 decode 优先让 prefill 付出的代价。
     - 叠加是近似，汇总里明说。
3. **故障集合：** 全集 19 个，还是只做 (a) 11 个，还是代表子集。
   - **推荐全集，按 无故障 → (a) → (b) 分批。**
     - 与 C 的表一一对应。
     - 用户的原则是需要的实验都要有结果。
4. **−CPCM 映射的消融：** 新跑 A1 起点上的 L2Gsync（按 ε 分轮），还是用 A1 + FULL-BusyBarn 代替。
   - **推荐新跑。** 只有这样才是“只去掉 CPCM 映射”。代价约 210–470 h，可以与 D2 同时在 Colab 上跑。
5. **CRISP 用 L2Gsync 的哪个种子：** 每个“故障 × 算子”取 5 个中后端均值的中位数那个（并列取小），还是 5 个全跑。
   - **推荐取中位数那个。** 5 个全跑会让最贵的按跳臂乘 5；C 已经给出了 5 个种子的修复后延迟分布。
6. **重叠单元的参数：** f ∈ {0.1, 0.4, 0.7}，种子 1–3，k = 1.5（P、D 相同）。
   - **推荐照此。**
     - 种子与 k 沿用 DSTU 的默认。
     - 三个 f 保证 D 链整条落在最短的 P（prefill LN）内。
7. **基线的后端：** 原后端（长度分层、不切块）作基线。
   - **推荐原后端。** 这是 BusyBarn 实际的仲裁。
   - 换后端本身的影响由 −DSTU 优先级臂（按跳、切块、P1）和“原后端对按跳的单独延迟”两项分开报告。
   - 按跳不切块的 P1 默认不跑。DSTU 已经测过：全链路切块 + C4 比“只切 D2D”和“不切”都好。
8. **单进程时限：** pf_mha（推测还有 pf_ln）的按跳完整运行与 T̂ 会超过 1 小时。
   - **推荐放宽到 3 小时**（同 C 对 prefill MHA、LN 的放宽），超时只报警。
9. **可选项：** 反序参照（+136 h）、FULL-A3h + DSTU（+218 h）、φ_res。
   - **推荐只加反序参照，且只在无故障与 (a) 组做（约 +82 h）。** 这样 CRISP 可以报 C4 − BestFixed，与 DSTU 的表同口径。
   - FULL-A3h + DSTU 与 φ_res 默认不跑。
10. **故障的时间语义：** 同 C，故障在请求开始前发生，修复完成后再服务。
    - **推荐照此。** 请求中途故障要另定窗口口径（EIR 阶段 B 的时间轴），不在 D 中做。
