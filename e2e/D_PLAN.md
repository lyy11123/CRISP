2026-11-11。第 1 版（2026-11-10，S-A 同组时分）见 git 历史（622e75c）。改版依据：

- 用户 2026-11-11 的场景改定（`E2E_HANDOFF.md` 第 6 节末“场景改定”）；
- D0（`D0_SUMMARY.md`）与 S-B 冒烟（`D_SMOKE_SUMMARY.md`）的实测；

耗时标“估”的都按冒烟实测折算（本机，8–10 个并行，含争用）；标“推测”的没有验证。

## 1. 场景

**主场景 S-B：** 2×4 平台。P 组是左边的 2×2（Die 0、1、4、5），D 组是右边的 2×2（Die 2、3、6、7）。

- **映射：** C 的 2×2 状态原样加载（T̂ 与 C 相同），改写 Die 编号：n·2 + m → n·4 + m（P 组）或 n·4 + m + 2（D 组）。核与 DDR 端口编号不变，不重新搜索。冒烟核实：同一状态在 2×4 与 2×2 上逐位相同（按跳与原后端）。
- **KV：** prefill MHA 最终广播中的 kconv（K）、vconv（V），单任务各 64 条、共 100,663,296 B。
  - 目的地改为 D 组的 32 个 DDR 端口；坏端口不在内，坏了的端口由平台去掉。
  - 用 artifact 的 Dijkstra 在 2×4 上重求多播树：按 tag 顺序，随机种子 BCAST_SEED，α、β、γ 取模板的值。
  - Kᵀ（ktrans）与 P（p_matmul）照旧留在 P 组。
- **P 流（流 0）：** 一个 prefill 算子，释放时刻 0。MHA 取 1 个任务，组装时乘 8。
- **D 流（流 1）：** 一个 decode 步的串行链 LN → MHA × 8 → 投影 → LN → FFN。
- **共用资源（冒烟核实，事实）：**
  - P 与 D 的非 KV 链路交集为空，计算单元不共用。
  - KV 与 D 共用 D 组的 co2co（118 条）、co2ddr（32 条）、ch2ch（11–12 条）；KV 与 P 共用 P 组的 co2co、ch2ch。
  - 组间 D2D 只有 KV 用。
  - 所以只有 P = prefill MHA 的单元有相互作用。
- **非 MHA 的 prefill 算子（LN、投影、FFN）：**
  - 与 D 不共用任何资源，结果只受两条流交织时随机平局的影响。冒烟中 pf_ffn 的重叠：D 链 250,329 对单独 249,522，P +1,860。
  - 规则：这些算子不跑重叠单元，ΔP 记为 0，TPOT(p) 取 D 链单独值。每个故障组只留 1 个核对单元（第 5 节）。

**S-A 缩小版（现象报告）：** P、D 同在一个 2×2 组（D0 的代码）。只为报告“共置时计算不可抢占，主导 TPOT”。

- 条件：无故障、PF4（D2D）、PF6（只坏 PE）。
- 臂：B-R0（原后端）、CRISP、−DSTU 优先级。
- P ∈ {pf_mha, pf_ffn}，f = 0.4（τ = f × 该臂 P 单独均值），种子 1–3。

## 2. 臂

| 臂 | 映射与修复 | 后端与仲裁 |
|---|---|---|
| B-R0 | A1，R0 | 原后端（`e4_backend.event_driver_e4`），不切块 |
| B-FULL | A1，FULL-BusyBarn 胜者 | 原后端 |
| **CRISP** | A3h，EIR L2Gsync 停止档（ε = 2%） | 按跳后端（`d_hop`），全链路 256 KB，C4 |
| −DSTU | 同 CRISP | 原后端 |
| −DSTU 优先级 | 同 CRISP | 按跳后端，全链路 256 KB，P1 |
| −EIR | A3h，R0 | 按跳后端，256 KB，C4 |
| −A3h | A1，EIR L2Gsync 停止档（新跑，第 4 节） | 按跳后端，256 KB，C4 |
| 反序参照 | 同 CRISP | 按跳后端，256 KB，固定顺序 P 先 |
| 无 KV 对照 | 同 CRISP 或 B-R0，KV 不改写（留在 P 组，P 与 D 不共用任何资源） | 同所属臂 |

- **无 KV 对照的用途（冒烟发现）：** pf_mha 的配对 ΔP 在没有任何共用资源时也有 −0.33M 到 0（PF4 放在 P 组，3 个种子），量级与 P 单独的种子极差（0.55M）相同。它给出 ΔP 的噪声分布，与 KV 单元并列报告。
- **C4 的顺序：** 两条流时 d̂_D = τ + 1.5·T̂_D 小于 d̂_P = 1.5·T̂_P，C4 让 decode 先走。冒烟（无故障，g = 0.4）：D 链 268,176（C4）对 280,472（P1），单独 249,522。
- **φ_res、FULL-A3h + DSTU：** 不跑。

## 3. 故障

| 组 | 坐标 | 该组的状态 | 另一组 |
|---|---|---|---|
| P 组 | C 的 19 个，(a) 11 个 + (b) 8 个，改写进 P 组 | 各臂取 C 在该故障上的状态 | 无故障状态 |
| D 组 | 同上，改写进 D 组 | 同上 | 无故障状态 |
| 组间 | G1：Die 1–2 的一对 D2D 双向坏（(1,11)↔(2,8)）。G2：Die 1–2 之间的两对都坏（再加 (1,7)↔(2,4)），KV 只能走 Die 5–6 | 两组都是无故障状态；只有 KV 的多播树改变 | — |

- **推荐全跑（41 个条件 = 无故障 + 19 + 19 + 2）。**
  - D 组故障直接作用在 decode 与 KV 交汇的地方，是 DSTU 的主战场。
  - P 组故障改变 TTFT 与 KV 的源头。
  - 组间故障是 S-B 才有的新类别。
- **C 的语义不再成立：** “同一物理故障同时作用于 P 和 D”不适用，汇总写明。
- **组间故障下没有 EIR 级别：** KV 的多播树由 Dijkstra 在坏链路之外重求，这本身就是“只改路由”的修复。各臂的映射与无故障相同。
- **已知的地板：** 14 个含 PE 失效的故障，放在 P 组时，prefill 投影、FFN 有鸽笼下界（`C_SUMMARY.md` 第 4 节）。汇总里单列。

## 4. 状态取法

同第 1 版第 3.1 节；“−CPCM 映射”改名为“−A3h”。

- **CRISP（及 −DSTU、−DSTU 优先级、反序参照、无 KV 对照）：** 按 `c_report.json` 的停止档。
  - 停在 R0 或 L1：用 l1 作业的快照。
  - 停在 s30、s100、s300：取该档 5 个 SA 种子中 C 后端 10 种子均值等于中位数者，并列取种子号小者。
- **−EIR：** A3h 的 R0。**B-R0：** A1 的 R0。**B-FULL：** A1 FULL-BusyBarn 胜者。
- **−A3h：** A1 起点上新跑 L2Gsync，规则同 C（5 个种子，ε = 2%），按 ε 分轮。
  - 先用 C 已有的 A1 L1 判断：已进 ε 的算子停在 R0 或 L1，不跑 L2。
  - 其余算子跑 s30；仍不满足停止规则的跑 s100，再 s300。
  - 停止档的种子取法同 CRISP。
- **加载后自检：** 每个状态加载后 T̂ 必须与 C 存的值相同，D0 已验证 48/48。

## 5. 单元与运行清单

**单元：** 臂 × 条件 × P 算子 × g × 种子，P 算子只有 pf_mha 有重叠单元。

- **τ 按公共参照的 KV 窗口定位：** τ = t_KV,s + g × (t_KV,e − t_KV,s)，g ∈ {0.1, 0.5, 0.9}。
  - (t_KV,s, t_KV,e) 是健康 W1 基线（A1、无故障、原后端、S-B 平台）pf_mha 单独运行种子 1–3 的 KV 窗口的均值：833,096、4,546,804。
  - 对应 τ = 1,204,467、2,689,950、4,175,433。所有臂共用，开跑前固定。
- **为什么不用 f × T_P：** 冒烟里各状态的 KV 窗口约为 0.82M–1.04M 到 4.4M–5.5M。若按 f × T_P 取 τ，f = 0.1 时 τ ≈ 0.64M–0.71M，decode 链（约 0.25M）在 KV 开始前就跑完，等于单独运行。按窗口定位，3 个 g 都落在冒烟见到的各状态窗口之内。
- **窗口外的单元等于单独运行：** 若某个状态的 KV 窗口与 [τ, τ + T_D] 不相交，该单元与单独运行只差随机平局。汇总逐单元列出 τ 是否在该状态的实际窗口内。

**每个“臂 × 条件”的运行（完整运行，不用停止模式）：**

| 内容 | 次数 | 什么时候跑 |
|---|---|---|
| P 单独，4 个算子 × 种子 1–3 | 12 | 该条件下 P 组的状态与已跑过的不同（无故障、P 组故障；组间故障只跑 pf_mha） |
| D 链单独，种子 1–3 | 3 | D 组的状态与已跑过的不同（无故障、D 组故障） |
| C4 的 T̂：pf_mha、D 链 | 2 | 按跳 C4 的臂，状态不同时 |
| 重叠：pf_mha × 3 个 g × 3 个种子 | 9 | 每个条件 |
| 无 KV 对照的重叠：pf_mha × 3 个 g × 3 个种子 | 9 | CRISP 与 B-R0，每个条件 |
| 非 MHA 核对单元：pf_ffn × g = 0.5 × 种子 1 | 1 | 每组故障的第一个条件与无故障（共 3 个） |

**去重：**

- 同一个导出状态（同一快照）在多个臂上共用单独运行。例如 C 的停止档为 R0 时，CRISP 与 −EIR 的状态相同。
- 单流时 C4 与 P1 逐位相同（D0 第 5 项），所以 −DSTU 优先级只跑重叠。
- P 组故障下 D 链用无故障的结果，D 组故障下 P 用无故障的结果。
- 组间故障下，非 MHA 的 P 算子与 D 链用无故障的结果。

## 6. 指标

**直接仿真量（主结果）：**

- **D 链延迟：** C_D − τ，逐单元列出；相对公共参照 T_D,ref = 355,201（A1、无故障、原后端，D 链单独，种子 1–3 均值）。
- **ΔP：** 配对，C_P（重叠）− C_P（单独），并列无 KV 对照的 ΔP 与 P 单独的种子极差。
- **公共截止时间下的迟约：** dᵢ = rᵢ + 1.5·Tᵢ,ref，L̂ᵢ = (Cᵢ − dᵢ)/Tᵢ,ref。
  - T_P,ref：pf_ln 2,186,864，pf_mha 6,388,643（含 KV 写到 D 组），pf_proj 6,560,063，pf_ffn 44,532,443。
  - T_D,ref = 355,201。
  - 报 L̂_D、L̂_P、L̂_max、违约流数。
- **KV 完成时刻：** KV 消息（含切块）的最晚结束时刻减 0。
- **第二套指标：** 各臂相对自身单独时间的放大，即 (C_D − τ)/T_D,self、C_P/T_P,self。

**解析外推（第二层，标明“基于单次重叠的解析外推”）：**

- TPOT′ = TPOT_iso + w_MHA × (TPOT(mha) − T_D,self)。
  - TPOT(mha) 是 pf_mha 重叠单元的 D 链延迟（对 g、种子取均值）；其余 prefill 算子的 TPOT(p) = T_D,self。
  - w_MHA = 8·T_MHA / (2·T_LN + 8·T_MHA + T_proj + T_FFN)，用该臂自身单独时间。
- TTFT′ = TTFT_iso + 8 × ΔP_mha × (8·T_MHA / TPOT′)。
  - 假设 decode 持续，每个 MHA 任务期间插入的 decode 步数 = T_MHA / TPOT′。
  - 用 ΔP 的配对均值；不显著（落在无 KV 对照的范围内）时同时给出 ΔP = 0 的值。
- 请求延迟：R-iso 与 R-ov 两种，输出 128、512、2048。
- **线性检查（冒烟已做 1 例）：** 连续 8 个 decode 步，每步 249k–286k，单独 248k–250k。
  - decode 一侧增量大体均匀，可以线性叠加。
  - P 一侧 ΔP 不随步数增加：8 步时 +210k 到 +286k，1 步时 +263k；P1 与 C4 的符号也不同。
  - 所以 TTFT′ 的外推不可靠，只作第二层。

**迁移量与修复步数：** 引用 C（同一状态）；−A3h 用新跑的。

## 8. 停下报告的情况

- 自检不通过：T̂ 不等、平台结构不符、KV 守恒或树检查失败、审计不符、释放违例。
- 模板或后端报错。
- 单进程内存超过 3 GB，或系统空闲低于 3 GB。
- 单进程超过 1 小时（pf_mha 放宽到 3 小时，只报警）。
