## 3. 统一排程与工作量

### 3.1 共享池的执行顺序

1. 核对当前源码与输入版本，导出本轮任务清单；若用户本地已比本文件提交更新，复用身份一致的已完成项。
2. **优先启动 B 的两条 prefill FFN / PF4 长链。** 两种硬件彼此独立，先运行健康重放和 R0/L1。
3. A 的独立 1000 步入口就绪后，立即加入五个修复作业；A 不等待 B。
4. 同步处理 P0 文档和 CSV 后处理。
5. C 完成真实 MF6 锚点与代表点选择、S 完成 A1-EIR 接入后，分别把就绪任务加入共享池。
6. 各包依赖满足即运行，完成即汇总；无需等待其他包才能交付本包结果。
7. 质量池清空后，在同机空闲窗口补 J。J2b 可以作为最后一个独立长任务。

运行中的作业使用冻结的源码与配置副本。新接口开发在工作副本中完成，验证后再加入任务池，避免修改正在运行的公共模块。

### 3.2 并发与估时

- 沿用当前服务器的 **128 个单线程进程上限**，根据实际分配 CPU 和可用内存调整；不把 128 vCPU 写成 128 个物理核。
- 数值库和 Numba 每进程维持单线程；沿用系统内存余量，至少保留原方案的 3 GiB，并观察实际 RSS。
- B 每点每档最多五条修复种子同时执行，两点通常最多约十个重型修复作业同时就绪。
- 按剩余依赖链长度优先调度，轻任务填充其他槽位。无就绪任务时允许正常空闲。
- 保留现有单作业内十种子后端评估顺序，外层统一调度；本轮不另做嵌套并行改造。
- 首批 R0/L1 或一个完整预算作业结束后，更新每类实测时间、剩余进程小时、最长依赖链和预计结束时间。

估时同时考虑总工作量与依赖关系：

\[
W_{\mathrm{wall}}
\gtrsim
\max\!\left(
\frac{\mathrm{PH}_{\mathrm{remaining}}}{p_{\mathrm{effective}}},
C_{\mathrm{longest\ dependency\ path}}
\right).
\]

两条 B 长链在全部预算执行时，初始各约 5～6 小时；这不是全池固定完成时间，也不包含尚未完成的接口开发。原停止规则提前结束某些点时，实际成本会减少。

### P0.2 64 组 CPCM 选优损失

输入：e2e/hi/tables/h3_i2_candidates.csv 及对应原始记录。

分组键：模型、硬件、阶段、算子、方法；每组 14 个候选。比较：

1. 各方法自身代价；
2. 统一确定性 CPCM；

- 选中候选 ID；
- 后端最优候选 ID；

- 选优损失；
- 候选 ID 命中、零损失命中；
- 全组中位数、P90、最大损失。

\[
r_{\mathrm{select}}=
\frac{T_{\mathrm{backend}}(m_{\mathrm{selected}})}
{\min_{m\in\mathcal C}T_{\mathrm{backend}}(m)}-1.
\]

当前复算检查值：随机 CPCM 命中同一后端赢家 53/64，损失中位数 0%，最大约 3.67%；统一确定性为 38/64、最大约 12.52%；自身代价为 16/64、最大约 142.86%。使用原始精度复算，表中说明这是选择损失而非估值误差。[R6]

### P0.3 H5/I5 干扰与 KV 窗口

输入：h5_joints.csv、i5_joints.csv 及匹配的单跑记录。

每行计算：

\[
I_D=\frac{D_{\mathrm{joint}}}{D_{\mathrm{solo,\ same\ backend}}}-1.
\]

按同条件、实验臂、相位和种子保存原值，再给出中位数与范围。负值保留，并解释为两次执行的随机仲裁轨迹差异。

窗口表包含：

- 模型、条件、实验臂、相位、种子；
- 统一参考的 D 释放时刻 \(\tau_D\)；
- 当前运行实际 KV 的开始、结束时刻；
- D 完成时刻；
- KV 时间窗口与 D 存活窗口是否相交；
- D 联合延迟、同后端 D 单跑、P 绝对完成时间。

实际后端窗口写作 \(t^{\mathrm{backend}}_{\mathrm{KV,start/end}}\)，仅 CPCM 预测使用帽号。窗口相交说明存在时间重叠，不等于已测得同量的队列阻塞。

图表横轴明确“基于共同 A1 参考的释放相位”。同一个 \(g=0.9\) 不是各策略自身 KV 已传完 90%。保留 H5/I5 的共同释放时刻，不按各方法重新对齐。

建议直接用这些数据画一张 KV 窗口与 \(\tau_D\) 对照图；无需新增联合仿真。

## 5. A：Qwen decode FFN / PF4 的 1000 步预算诊断

### 5.1 固定输入与成本

- 模型：Qwen3-MoE。
- 硬件：BusyBarn 默认 2×2，主硬件。
- 算子：decode FFN。
- 起点：现有 A3h 健康赢家及同一 PF4。
- 搜索起点：已有同一 L1 保存状态。
- 方法：既定 EIR 的 L2G+sync，动作、温度校准和目标定义沿用原规则。
- 独立预算：1000 步。
- 修复种子：{123, 1, 2, 3, 4}。
- 每个最终状态：后端种子 1–10。

合计 **5 次搜索＋50 次最终后端**。原 30/100/300 结果保留为主协议；1000 步作为后续预算配置诊断。

### 5.2 必须采用独立诊断入口

当前代码中：

- hi_fault.child() 只允许冻结的 30/100/300 步；
- fg_fault.child() 在 previous_stop.stop 为真时直接复用旧状态；
- fg_fault.stop_job() 将 300 步作为预算终点。

因此，1000 步任务使用独立 job 前缀和诊断入口，直接从保存的 L1 启动，不能挂在 stop300 后继承其停止标记。原 300 步控制器保持不变。完成记录必须确认实际 search_proposals=1000、起点身份匹配，并给出独立诊断结束原因。[R7][R8]

只验证新入口的必要行为：能执行完整预算、检查点记录不改变随机状态和轨迹、最终状态合法。既有大规模回归直接复用。

### 5.3 收敛数据：复用现成接口

eir.search() 已提供只读最佳状态检查点，child_rep() 能透传。使用：[R9]

~~~text
checkpoints = [30, 100, 300, 500, 700, 1000]
ck_backend = False
~~~

保存：

- repair_seed、总预算、检查点步数；
- best_E、best_T、best_step；
- 最佳状态快照；
- 累计搜索时间；
- 接受次数、校准成本和最终实际步数。

搜索的最优状态按既定能量 E 选择，其中包含微小距离项。因此曲线标为“当前搜索最优状态对应的 \(\hat T\)”，不从包含拒绝提议的所有 T_new 中另取最小值。

输出分成两部分：

1. **独立预算终态表**：30、100、300、1000，各五个修复种子的后端与 CPCM。
2. **1000 步日程内检查点曲线**：30、100、300、500、700、1000。

温度日程随总预算变化，1000 步轨迹的第 300 步不替代原 300 步独立实验。检查点只记录状态，不增加中途后端样本。

### 5.4 关键链与等待分解

对健康、R0、L1、五条 300 步终态和五条 1000 步终态使用保存状态做 CPCM 解释。若缺少完整 Schedule，补一次固定配置 CPCM 推演并单列诊断耗时；无需增加后端种子。

输出两张不同含义的表：

**表 A：关键链时间构成**

- 类别：TensorCore、Vector、D2D、片内 NoC、DDR 接口、release/gap/other。
- 依照关键链边的 lag 或不重叠时间段分配，检查总和等于该次 \(\hat T\)。
- 按资源类型分类：DDR 发出的消息途经 NoC/D2D 的部分分别计入对应链路，不把整条消息都归为 DDR。

**表 B：关键等待归因**

- 使用 CPCM Analysis.blocking() 的默认排他归因 cb_excl；
- 分组统计各资源类别和最主要资源的阻塞时间；
- 同时列后端总延迟，展示模型解释与实测总成本的关系。

CPCM 的 hop 活动可能重叠，直接累加所有活动的 f−s 再加 wait 会重复计数。时间构成与等待归因是两个视角，不再互相相加。若暂时无法得到严格可加的时间构成，先交付 cb_excl 绝对等待量及资源负载表，不绘制强行加总到 100% 的饼图。[R10]

这些图标注为 **CPCM 时序解释**。已有后端只测总延迟时，不将它们标为逐事件后端实测。

### 5.5 完成后的判断

- 若 1000 步显著改善：说明该 MoE 图在当前方法下需要更大的恢复预算，同时报告新增决策成本。
- 若改善很小：结合关键等待、剩余链路负载与迁移解释当前恢复边界。
- 仅有平台期不能证明已达拓扑容量极限；只有建立相应负载/容量下界并与实测接近时，再作该结论。
- 1000 步不恢复到健康也按原样交付，本轮不自动追加更长预算或全硬件 FULL。

产物：A_QWEN_DFFN_BUDGET.md、独立预算表、检查点表、关键链构成/等待表、五个最终状态及 50 个后端样本。

## 7. C 与 S：机制补齐和系统八组合

### 7.1 C：先固定真实 MF6，再确定代表算子

目前完成的是静态合法轴预筛，真实 MF6 锚点后端尚需运行。沿用原计划的顺序：[R2]

1. 每模型使用健康 A3h decode MHA，运行后端 seed1 的忙碌统计。
2. 按非角落 PE 的既定规则固定一个 MF6，平局使用既定坐标顺序；故障对象与 router/计算单元范围沿用现有 MF6 实现。
3. 根据孤儿 Tensor 工作量和合法轴，在查看修复效果前选定一个 prefill FFN 或 projection 代表点。
4. 每模型只做一个机制点。若固定 MF6 对候选算子没有合法孤儿块，则报告 N/A；不因结果不理想而重新寻找有利故障位置。

### 7.2 C：四臂与健康/下界

| 对照 | 作用 |
|---|---|
| 健康 A3h | 故障前性能、负载与迁移参考 |
| A3h-R0 | 合法映射恢复后的初始损失 |
| rigid EIR | 原有刚性计算块下的搜索修复 |
| Local-m1 | 只有局部重放置，没有切分 |
| Split-m2 | 局部重放置与二分计算块 |
| 固定块计算负载下界 | 解释刚性粒度是否限制恢复空间 |

四个故障臂的最终对比状态各报告十后端种子。rigid EIR 内部仍运行原五修复种子及 30/100/300 独立预算和停止规则，不能把内部成本压缩为一次最终评估。

Local-m1 与 Split-m2 使用相同局部输入和既定放置/路由规则。切分轴沿用已有非后端选轴规则，报告所有合法候选轴及最终选轴原因。保留实际输入复制、通信、唯一迁移块字节和 FLOP 取整结果，不预设切分后所有通信都按 1/m 缩小。

### 7.3 C：下界使用真实计算块时长

对同构 TensorCore 资源，复用 post_fg_split.tensor_bounds()，令块时长为 \(c_j\)、块数为 K、可用单元数为 \(P_{\rm avail}\)：[R12]

\[
LB=
\max\!\left(
\max_j c_j,\;
\frac{\sum_j c_j}{P_{\rm avail}},\;
\left\lceil\frac{K}{P_{\rm avail}}\right\rceil\min_j c_j
\right).
\]

等时长块时才简化为：

\[
LB=\left\lceil K/P_{\rm avail}\right\rceil c.
\]

同时报告最忙核实际计算负载、块时长分布、实际延迟及通信成本。负载接近该下界说明当前固定分片的紧致程度，不自动等同于端到端最优。

C 两点在复用健康参考时，最大新增后端为：

- 2 次 MF6 锚点；
- 40 次 R0/L1；
- 最多 300 次 rigid L2 评估；
- 40 次 Local-m1 / Split-m2；
- 合计最多 382 次。

需新做健康重放时再增加 20 次，合计 402 次。实际数量随停止规则与合法性减少。旧三个 Split 案例的 63 次补充已完成，直接复用。

产物：C_NEW_MODEL_SPLIT.md、语义/工作量核对、四臂质量表、负载下界表、迁移与通信表。
