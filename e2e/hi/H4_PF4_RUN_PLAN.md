# H4 PF4 与 A1-R0 运行计划

2026-11-14。Llama 健康448个候选已齐，新增主硬件8个PF4算子点、WATOS4个PF4算子点，以及供H5使用的主硬件4个decode A1-R0状态。本轮不执行MF6或H5联合仿真。

## 输入与方法

健康输入索引见 `manifest/h4_healthy_inputs.json`：224个候选的原结果、raw和snapshot均已核对SHA-256，位于h1_main、next_344、h3_i2_440。每组14候选按十后端均值、candidate_order平局顺序选优；随机CPCM所选候选另记。直接引用这些文件，不重新搜索健康映射。

PF4固定为die0/core11与die1/core8双向D2D边；加载平台验证两条物理边，不调用MF6忙碌排名后端。主硬件8个点为P/D的LN、MHA、projection、FFN；WATOS仅P/D MHA、FFN。4个A1输入只做R0，不做A1-EIR。

EIR沿用原R0、L1、L2G+sync，五个修复种子123、1、2、3、4，各30、100、300步档位均从同一L1独立启动。停止阈值和温度规则不变：跨级回到健康估值2%以内才停；档位取五种子平均估值，100/300档相对上一档改善不足2%停止，300档达到预算停止。联合代表为五个结果的后端中位样本。搜索接确定性bb加速、关闭逐步checks、保留精确回滚；最终评估用原实现，每状态十个后端种子1–10。

## 作业数量

264是调度作业总数，包含52个选择、故障定义与停档判断作业；16个健康重放；16个R0/L1作业；最多180条L2独立轨迹。原停止规则会让后续轨迹作业写出复用记录，复用记录不算实际修复搜索。上限2240次后端：健康160、A3h R0/L1 240、A1-R0 40、L2最多1800。

## 本机实际验证

已验证主硬件decode MHA、A3h候选g1/seed123：健康快照重放T̂=12107，与原结果精确相同；PF4后R0=12688，L1=12202，距健康+0.785%，原停止规则自然选择L1并停止。五个准备/验证作业合计约54.1秒本机墙钟，最大进程RSS 0.464GiB。

另从该真实L1状态直接调用原30步L2引擎作接口验证，T̂=12109，十后端均值12109；总16.15秒，其中校准0.315秒、搜索0.407秒、十后端12.126秒。自然stop记录保持true，接口验证不纳入正式轨迹结果。健康、R0、L1、接口验证的raw均核对种子1–10，共40个本机后端样本。证据在 `evidence/h4_pf4_smoke.json`，原文件在 `out/h4_pf4_smoke_20261114`。

## 资源与时间

正式目录 `out/h4_pf4`。两批健康搜索保持运行。H4每轮为H3/I2的440项及I3的108项中所有未取得有效成功回执的任务保留名额，包括尚未启动或可能重试的项；H4只使用剩余槽位。因此三个池合计最多128进程。内存读取系统可用量，扣除三个池未来增长预算并预留3GiB。内存失败记录保留，有余量后自动重试。

按全部180条L2轨迹都执行的初始估计为3.48进程小时；14个可用槽约16.3分钟，32个及以上约11.3分钟（依赖链限制）。安排约15–35分钟，并随实测更新；包含搜索、全部后端和状态导出，下载、汇总另计。后续自然停档会减少实际轨迹。
