## 0. 目标、定位与阶段

E4a 的结论（数字见 `E4A_SUMMARY.md` 第 3 节）：在按跳仲裁的后端上，非对称两条流、三条流时，最好的固定流级优先级（短优先）使 S_max 降低 35–47%，故障后同样成立；a2（MHA+FFN）需要再加 D2D 切块（256 KB，无故障 43%、F4 68%）；相对 FCFS 仍有 20–66% 的额外收益。但 E4a 的截止时间都是 dᵢ = rᵢ + k·Tᵢ（同一个 k），此时静态 slack 顺序恒等于“短优先”，**slack 与 SJF（短作业优先）无法区分**；固定顺序也只是在 2 条流的 2 种顺序中挑一个。

E4b 回答三个问题：
1. **同乘子 k 下**，按跳、按剩余截止时间动态仲裁（DSTU）能否自动达到 E4a 中“最好固定顺序 + 切块”的收益；
2. **异构截止时间下**（截止时间与流长度不成比例），DSTU 是否优于 FCFS、SJF、静态 EDF；
3. **是否存在所有固定顺序都会输的情形**（slack 随时间交叉、3 条流混合截止时间），DSTU 相对“事后最好的固定顺序”（BestFixed）能多得多少。

**定位**：E4b 在内存中实现 DSTU 的仲裁规则，属于判定关口之后的模块原型。用户已同意进入（2026-11-02 主会话），用户应在方案文档中记录该决定。E4b 仍只在仿真器中做比较，不改 `third_party\`，不实现 CPCM、EIR。

**场景说明（论文叙事用）**：
- 设定 2 中“长流截止时间紧、短流宽”对应方案第八节场景 3：长流位于流水线关键路径上（下一层在等它），短流是给后续 micro-batch 的预取，余量大。**不要称为 PD 共置**：真实 PD 共置中 decode 又短又紧，slack 与 SJF 给出同一顺序，作为对照组保留（设定 2 的“反向”）。
- E4c（请求到达、goodput、P99、与 DistServe/Splitwise 静态分离的完整比较）不在本说明范围；本说明只加一个静态分区的代理基线（2.2 节 P8，2 条流配置上做）。

## 2. 方法定义

### 2.1 截止时间与指标

- 第 i 条流：释放 rᵢ、完成 Cᵢ、单独延迟 Tᵢ、截止时间 dᵢ = rᵢ + kᵢ·Tᵢ（kᵢ 可因流而异）。
- **主指标：归一化最大延误 L̂_max = maxᵢ (Cᵢ − dᵢ) / Tᵢ**。L̂_max ≤ 0 ⇔ 所有流满足截止时间。kᵢ 全相同时 L̂_max = S_max − k，与 E4a 一致。
- 其他：各流放大倍数 (Cᵢ − rᵢ)/Tᵢ、S_max、违约流数、整体完成时间、流水节拍。
- 违约率只在多组截止时间（设定 2 网格、设定 3 随机抽样）上统计，不对单个配置报告。
- 所有量取 3 个后端种子的均值，另报种子极差。

### 2.2 策略（优先级键，键小者先发）

| 编号 | 名称 | 键 | 说明 |
|---|---|---|---|
| P0 | 原后端默认 | — | 长度分层 + 路径长者先，只作参照 |
| P1 | 按跳默认 | 剩余路径长度（长者先） | 无流优先级 |
| P2 | FCFS | (rᵢ, 剩余长度) | 早释放者先 |
| P3 | SJF | (Tᵢ, 剩余长度) | 静态，短流先 |
| P4 | 静态 EDF | (dᵢ, 剩余长度) | 静态，截止早者先 |
| P5 | BestFixed | 对所有 n! 种固定流顺序各跑一遍，事后按 L̂_max 均值取最好 | 不可实现的参考；2 条流 2 种、3 条流 6 种 |
| P6 | DSTU-s（流级 slack） | (slackᵢ(t), 剩余长度) | slackᵢ(t) = dᵢ − t − R̂ᵢ(t)，每次仲裁时重新计算 |
| P7 | DSTU-e（事件级 slack） | (dᵢ − t − tailₑ, 剩余长度) | tailₑ = 该通信事件自身占用时间 + 单独运行图中从它结束到所属流终点的最长剩余路径（与 E2 的 tail 相同） |
| P8 | 静态分区代理（用户已决定做，只用于 2 条流） | 按跳默认 | 相邻 Die 间每方向 2 条 D2D 链路按流各分一条，各流只用自己的那条；见下文 |
| P6′ | DSTU-s′（归一化流级 slack；用户 2026-11-02 加入） | (slackᵢ(t)/Tᵢ, 剩余长度) | slackᵢ(t) 同 P6；Tᵢ、R̂ᵢ 的切块取法同 P6 |
| P7′ | DSTU-e′（归一化事件级 slack；用户 2026-11-02 加入） | ((dᵢ − t − tailₑ)/Tᵢ, 剩余长度) | tailₑ 同 P7，切块时按下文更正后的口径（计入尚未发放的兄弟块） |
| P7m | DSTU-em（修正变体；用户 2026-11-02 加入） | ((dᵢ − t − remₑ(t))/Tᵢ, 剩余长度) | remₑ(t) = max(R̂ᵢ(t), tailₑ)；R̂ᵢ 同 P6′，tailₑ 同 P7′ |
| P7m_raw | P7m 的原始时间版（用户 2026-11-03 加入） | (dᵢ − t − max(R̂ᵢ(t), tailₑ), 剩余长度) | R̂ᵢ、tailₑ 同 P7m，只是不除以 Tᵢ |
| P6h | 迟滞（用户 2026-11-02 加入；θ = 0.05、0.10） | (流在保留顺序中的位置, 剩余长度) | 以 P6′ 的键为基础：流在释放时按当时的键插入顺序；之后每个新的仲裁时刻比较相邻两流，挑战者的键比前面的流小 θ 以上才交换（重复直到不再交换） |
| P6v | 已违约降权（用户 2026-11-02 加入） | (slackᵢ(t) < 0, slackᵢ(t)/Tᵢ, 剩余长度) | 预计已违约的流排在其余流之后，两类内部按 P6′ 的键 |
| P7mv | P7m + 已违约降权（用户 2026-11-02 加入） | (slackᵢ(t) < 0, P7m 的事件键) | 是否已违约按流级 slackᵢ(t) = dᵢ − t − R̂ᵢ(t) 判断 |

**流级排序翻转**（用户 2026-11-02 加入，P6、P6′）：只看至少两条流都有就绪通信事件的仲裁 tick，按各流的键排序；相邻两个这样的 tick 之间任意一对流先后交换记一次；另报最后一次翻转时刻占 makespan 的比例、翻转时双方 slack 是否都已为负。

**原始最大延误**（用户 2026-11-02 加入）：所有策略另报 L_max = maxᵢ (Cᵢ − dᵢ)，单位周期，与 L̂_max 并列；并报告按 L_max 排名与按 L̂_max 排名是否不同。

剩余工作估计 R̂ᵢ(t)（P6）第一版用**理想估计**：按单独运行的轨迹，把流 i 已完成的工作量（已完成事件在单独运行中的占用时长之和）映射到单独运行的时间轴，R̂ᵢ = Tᵢ − τᵢ，τᵢ 为单独运行中完成同样工作量的时刻。P7 的 tail 也来自单独运行图。两者都相当于“理想的 CPCM”；论文中须与以后的 CPCM 估计分开报告。实现前先在 PROGRESS 写明具体做法。

**切块时 P6、P7 的口径**（用户 2026-11-02 提醒）：切块把一条原消息 m 拆成 m⁽¹⁾…m⁽ᵐ⁾ 个同路径、互不依赖的块，下游要等所有块到齐。若对每块单独算“从该块结束到流终点的最长路径”，第 1 块与最后 1 块的 tail 相同，会低估把整条消息传完还需要的时间（同一链路上还排着它的兄弟块）。规定：
- 块 b 在链路 ℓ 上的 tail_b(t) = 原消息 m 在 ℓ 上尚未发放的各块（含 b）占用时间之和 + tail(m)（2026-11-02 更正：原稿多减了一次 b 自身占用；按此式，不切块时 m 只有一块，tail 退化为“自身占用 + 剩余路径”，与 P7 的不切块定义一致），其中 tail(m) 是原消息 m 结束到所属流终点的最长剩余路径，在**同样切块**的单独运行图上取 m 的最后一块计算；
- P6 的 R̂ᵢ(t) 用同样切块的单独运行轨迹（Tᵢ 也按同样切块取）；
- 第 1 步在 PROGRESS 中写明实际实现，并在自检 3 中加入一个切块配置（a2 MHA+FFN，256 KB 只切 D2D，同 k、Δ0），检查 P6、P7 是否退化为短优先。

**P8 的口径**（用户 2026-11-02 决定在 2 条流配置上做）：
- 只用于 2 条流；每对相邻 Die、每个方向的 2 条 D2D 链路，流 0 一条、流 1 一条（哪条给谁固定且记录）。各流把不属于自己的那条视为失效，按 E3 的 R0 规则（保留路由，只对被切断的通信重新选路）得到分区后的路由。片内链路、DDR 出口不分区，仍按按跳默认仲裁共享。
- 放大倍数与 L̂_max 的分母仍用**不分区**的单独 Tᵢ，与其他策略一致；另报告各流在分区平台上单独运行的延迟，作为“分区本身的代价”。
- 硬件状态中某对 Die 某方向只剩 1 条 D2D 链路时（F4，或 F5 落在 D2D 上），该配置无法分区：记为“不适用”并报告原因，不另造替代方案。
- 只报数字；不要预设 P8 的结果。

DSTU 只作用于链路仲裁；计算单元仍按原后端规则（E4a 已确认计算事件不经过 Phase 4）。

### 2.3 场景

**设定 1：同乘子 k（复现 E4a 上限）**
- 组合：a1 512+8192、a1 2048+8192、a1 三条流 512/2048/8192、a1 对称 2048×2；a2 MHA+FFN（256 KB 只切 D2D）。
- 释放：Δ0、短先 0.5T、长先 0.5T（T 为最短流单独延迟）。
- 硬件：无故障、F4、F5。k ∈ {1.1, 1.5, 2.0}。
- 策略：P1–P7（P0 只在 Δ0 无故障各跑一次作参照）。P8 不再跑（2026-11-02 用户决定：第 1 步 a1 512+8192 无故障 Δ0 的一组 P8 数据作为代表性对照即可）。

**设定 2：异构截止时间网格（两条流）**
- 组合：a1 512+8192、a1 2048+8192、a2 MHA+FFN（256 KB 只切 D2D）。
- 释放：Δ0 与长先 0.5T。硬件：无故障、F4。
- 截止时间：k_long ∈ {1.1, 1.2, 1.5} × k_short ∈ {2, 3, 5}（长流紧、短流宽，场景 3）；另加反向对照 k_short ∈ {1.1, 1.5} × k_long ∈ {2, 3}（短流紧，PD 式）。
- 策略：P1–P7（P8 不再跑，同上）。

**设定 3：随机截止时间与交叉（三条流）**
- 组合：a1 512/2048/8192；a2 MHA、FFN、MHA（256 KB 只切 D2D）。硬件：无故障、F4。
- 每个组合 × 硬件抽 N = 20 组 (rᵢ, kᵢ)：rᵢ ∈ U[0, 0.5·T_min·i]，kᵢ ∈ U[1.1, 3.0]，随机数种子固定并记录。
- 策略：P1–P7（P5 含 6 种固定顺序）。
- 报告：每种策略的 L̂_max 分布、违约率；DSTU 严格优于 BestFixed（超过种子极差）的抽样比例与幅度；各抽样中 slack 顺序在重叠期间是否发生过交叉（记录 DSTU-s 的流排序变化次数）。

规模先实测再估算：总耗时预计超过 1 小时先告诉用户。若需缩减，优先保留设定 2 与设定 3 的无故障与 F4，设定 1 可只做 Δ0 与长先 0.5T。

## 3. 必须通过的自检

写进汇总；任何一项不通过，就报错停止。

3. **退化一致**：截止时间使 slack 顺序恒定时（例如同 k、Δ0），P6 与对应固定顺序（短优先）的结果一致；所有流 rᵢ 不同、截止时间按 rᵢ 排序且相同 kᵢ·Tᵢ 时，P4 与 P2 一致。
   判据（2026-11-02 用户决定）：影子比较中选中者全部相同，且 S_max 与对应固定顺序之差在噪声内（≤ 4%）；不要求逐种子完全相同（后端结果依赖对象地址）。
4. **仲裁审计**：随机抽查 ≥ 1000 次发放，被选中的候选确实是该链路该 tick 优先级键最小者。
5. **剩余工作估计**：单流运行（无竞争）时，沿轨迹 t − rᵢ + R̂ᵢ(t) 与 Tᵢ 的偏差（报告最大值与中位数）；偏差中位数超过 5% 先停下报告。

7. **开销**：DSTU 每次评估的墙钟相对 P1 的比例（只报告，不作停止条件）。
