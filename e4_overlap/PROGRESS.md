## 2026-11-01 第 2 步：合并、释放时间、S_max 上限、流级优先级（实现完成；自检 1 未通过，按第 7 节停下）

**实现**（新文件，均在 `e4_overlap\`）
- `e4_backend.py`：`event_driver` 第 282–527 行的逐行副本，改动处标 `# E4:`。不传 release/gate/prio 时代码路径、随机数调用与原版相同。
- 释放时间选 **(b)**：在内存中替换后端，某条流的无依赖事件的 `start_time` 设为该流的释放时间（原为 0），因此在释放时刻才会被 Phase 3/4 处理。理由：不引入虚拟事件和虚拟设备，事件图与原图同构（自检 1 的 graph_diff 可直接比较），E2 的关键链、归因和上限不需要剔除任何活动；代价是 E2 的 `Sim` 需要知道释放时间（见下）。
- 串行参照：同一后端副本中的门控：第 i 条流的无依赖事件先扣住，第 i−1 条流最后一个事件退场的时刻（Phase 2）再以当时时刻放入就绪表；实际释放时刻随结果返回。
- 流级优先级：Phase 4 的排序键改为（流的优先级，原来的剩余路径长度），其余不变；Phase 3 的计算派发不变。
- 合并（`e4_overlap.py`）：每条流从捕获的 pickle 还原原始事件对象，tag 第 1 位改为 10 + 流号，依赖集与发出集同步改名；改名后再次核对“通信 tag 的 `(0,)+tag[1:-1]` 是计算事件”。合并字典的顺序：流 0 的全部事件在前，各流内部保持捕获顺序。每个种子在一份新的对象和 deepcopy 的平台上仿真。
- `e4_attr.py`：原样调用 E2 的 `analyse`，只在调用期间把它的 `Sim` 换成子类 `SimR`：无依赖事件的最早开始 = 所属流的释放时间；关键链终止于这样的事件且 s > 0 时，在前面补一行 “release”（覆盖 [0, s]，不是等待、不作阻塞者、不属于任何资源，因此不进入归因、跨流占比和上限）；“从时刻 0 起”的最长路径（E2 自检 4、绕开某资源的最长路径）加上头部活动的释放时间，tail 不变。所有释放时间为 0 时与 E2 相同。
- S_max 单资源上限（`smax_resource`）：对 k 二分；给定 k，资源上第 j 项的截止时间 D_j(k) = min_i (r_i + k·T_i − q_ji)，q_ji 为从 j 完成到第 i 条流终点的最长路径（不含该资源自身的顺序边）。**与交接说明的差别**：交接说明写“所属流的 dᵢ − 到该流终点的剩余路径”；这里对 j 能影响到的每条流都取约束（其他资源的顺序边可能把 j 连到别的流），只看所属流会漏掉它对别的流的延误，上限可能偏乐观。可行性判定：当前顺序或 Schrage EDD 可行 → 可达（上界 k_ub）；抢占式 Jackson 不可行 → 不可能（下界 k_lb）；其间用 E2 的分支定界（≤ 14 项）。同时按 k ∈ {1.1, 1.5, 2.0} 给出最小 L_max。代码中检查：模型算出的当前 S_max 等于实际 S_max。
- 整体完成时间目标的对照：直接取 E2 `analyse` 的单资源重排结果（关键等待前 5 的资源），“删去资源”的上限 = (a − 绕开该资源的最长路径)/a。
- T_i 取合并工具单流运行（释放时间 0）的 3 个种子均值；T 取参与组合的各流中最短者。

## 2026-11-02 用户决定：串行参照改为解析值，自检 3 只查跨流阻塞

经主会话转达（用户原话："那如果不每条流单独跑，直接加和单独计算时间呢？"，确认后："发送并继续"）：
1. 汇总中的“完全串行”参照一律改为解析值：各流延迟 = 该流在同一硬件状态下单独运行的 Tᵢ，放大倍数 = 1，整体完成时间 = Σ Tᵢ，节拍 = Σ Tᵢ / 流数。Tᵢ 取 6 个种子均值：无故障与故障平台上已有的 3 个种子（种子 1–3）各补跑种子 4–6。
2. 自检 3 改为：已模拟的串行配置只检查跨流阻塞 = 0（硬性，不满足则停）；延迟差只记录（summary 的 `check3.latency_rel_diff`、`within_noise_stop`）。F4 的两个超标配置因此不算失败。
3. F5 与 1×4 的串行配置仍模拟，只用于检查跨流阻塞；第二批（切块）不跑串行配置。

**对交接说明的偏离**：交接说明的串行参照是模拟出来的串行运行，现改为解析值；自检 3 的延迟一致条件取消。

**实现**（`e4_overlap.summarize_config` 的 `check3.pass` 只看跨流阻塞；另写 `e4_serialref.py` 在两批结束后统一补种子与重算）：
